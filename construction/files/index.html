Files and naming standards

Files (left rail) holds every document that is not a model, a drawing set or a photo: specifications, reports, calculations, schedules, certificates, minutes, letters. Models, Drawings and Photos keep their own pages; the same naming standards check all of them.

Folders

Section titled “Folders”

The tree on the left works like the model tree: open and close folders, search them by name, and use the arrow keys. Project files is the top of the tree; Attachments holds files attached straight to an issue, a photo or a drawing. Above the tree:

  • All files and Recent (changed in the last 14 days);
  • Non-compliant, with the count of files whose names need fixing;
  • Attachments.

Coordinators and admins create, rename, move and delete folders: right-click a folder, or use the buttons above the tree. Each folder shows how many files it holds, an ISO badge when it checks names (blue: enforced, amber: warns) and a red count of files to fix.

Files and versions

Section titled “Files and versions”

Drop files on the page or on a folder in the tree, or press Upload. Uploading a file with the name of one already in the folder makes its next version; the earlier versions stay, each with who uploaded it and when. Uploading the same file again changes nothing.

In a folder with a naming standard the list splits each name into its fields (originator, type, role, number…), beside the title, version, status and revision. Select files to move several at once; drag files onto a folder to move them there.

Click a file for its panel: a preview, the name field by field, its versions and what it is linked to. Open shows the file full screen, page by page, with the same markup tools as drawings (arrows, clouds, freehand, text); markup is kept with the version for everyone and never changes the file.

Search reads names, titles, fields and the text inside PDFs and Word, Excel and PowerPoint files.

Note

PDFs and images have previews. Office files are previewed when the server has LibreOffice to convert them; otherwise they open by downloading them. Their text is searchable either way.

Naming standards

Section titled “Naming standards”

A naming standard lists the parts of a file name and the codes each may use, for example the UK National Annex to ISO 19650-2:

Project-Originator-Volume-Level-Type-Role-Number, such as HP01-KLA-ZZ-XX-SP-A-0001.

Under Settings › Naming standards (or the list icon above the tree), coordinators start a standard from a template (UK, Netherlands, Germany, the Nordics, or generic) and change it to the project’s own information standard:

  • the fields, in order, each a code from a list, a number of fixed width, or text; optional fields come last;
  • what is kept beside the name: title, status (S0–S7, A, B, CR), revision (P01, P01.01, C01), classification (Uniclass) and stage, each required, optional or off;
  • the project’s code lists, one code per line with its meaning, such as KLA KLA Architects.

Status and revision are values of the file, not part of its name, as the UK National Annex keeps them.

Checking names, folder by folder

Section titled “Checking names, folder by folder”

In a folder’s Settings a coordinator chooses its standard and how names are checked. Folders take their parent’s settings unless they set their own.

  • Off: names are not checked.
  • Warn: files whose names do not comply stay in the folder, flagged.
  • Enforce: files whose names do not comply wait in the holding area. Only the person who uploaded them, and coordinators and admins, see them until the name is fixed.

Checking is off until a coordinator turns it on. Files already in a folder that starts enforcing are flagged, never hidden. Attachments are never checked, so a quick attachment never waits.

A folder also sets defaults (an originator, a role, a type) suggested for its files, and who sees it: everyone, or contributors, coordinators or admins and above.

The Non-compliant view

Section titled “The Non-compliant view”

Every file, model and drawing set whose name does not comply, in one list: held ones first, what fails in words, and a suggested name. Suggestions come from the parts of the name that already comply, the folder’s defaults, the next free number and, when the organisation has AI on, the file’s own text and title block.

  • Fix one: click it, choose each field from its code list (a suggested value is one click), and press Save and release. A name that now complies leaves the holding area; a name already in the folder adds the file as that file’s next version.
  • Fix many: select them and press Use suggestions, or Set a field… to give them all one value.
  • Reject (coordinators): a held file can be rejected with a reason. The uploader is told why, and the file is removed after 30 days.

Contributors see their own uploads here; coordinators and admins see everyone’s. Needs attention shows the files you uploaded that need a new name, and, for coordinators, files held for more than two days.

Models and drawings

Section titled “Models and drawings”

The same standards can check model names and sheet numbers (Settings › Naming standards › Models and drawings), with the same off, warn and enforce.

  • A held model version is not made current, so it is not in the 3D federation, until it is renamed in the Non-compliant view. A model of that name already in the project takes it as its next version.
  • A held drawing set stays out of the register until its sheet numbers, read from the title blocks, are corrected there.

Attached to records

Section titled “Attached to records”

Issues (RFIs and snags too), photos, drawing sheets and each markup on them, and models show their Files. Attach uploads a file (it lands in Attachments) or links files from the project’s folders. A link follows the file’s latest version; a link kept on an older version says so when a newer one exists. A link never shows a file to someone who cannot see its folder: they see that a file is there, not what it is.

With the assistant

Section titled “With the assistant”
  • Which documents mention fire doors, and what do they say about riser doors? The assistant searches the files, reads them and answers with the files it used; click one to open it on the right.
  • Which files still have names that don’t comply? Propose names. The new names come on a card; nothing changes until you press Rename.
  • Attach the fire stopping certificate to issue 12.

Who can do what

Section titled “Who can do what”

Viewers see the files in the folders open to them. Contributors upload, add versions, attach files, draw markup and fix their own held files. Coordinators and admins manage folders, naming standards and code lists, move, rename and delete any file, and fix or reject anyone’s held files. Every change is kept in the audit log.

Note

AECX supports ISO 19650 naming; it does not make a project compliant. The project’s own information standard decides the codes, which is why every code list can be changed. Approval states (work in progress, shared, published) are planned separately.
